# 架构约定

## 组织方式

- 使用 monorepo；插件位于 `packages/<name>/`。
- 每个插件独立打包、独立安装。包名、构建和发布方案在实现调研后确定。
- 插件之间不建立强制运行时依赖，不读取彼此的私有文件或内部状态。
- 跨插件协作使用可选的公开接口或事件。缺少集成方时，插件自身功能仍可正常运行。
- 当前不创建公共核心包；出现明确、稳定的复用需求后再决定是否抽取。

## 状态与展示

- 执行状态与 UI 分离。文字输出和未来的面板使用同一套公开状态来源。
- Subagent 拥有自己的运行生命周期、结果与错误语义。
- 未来的任务规划插件拥有计划步骤及其完成、阻塞和验收状态，可关联 Subagent 运行 ID。
- 子 Agent 执行完成不等于计划步骤验收完成。
- 面板负责观察和通过公开接口发出控制请求，不成为执行状态的另一个事实来源。

## 开发原则

- 使用 Pi 已提供的能力，避免重新实现底层会话框架。
- 参考成熟实现的问题处理与测试，不直接继承整个产品的功能范围。
- 从可验证的最小执行闭环开始，按实际需求增加能力。
- 工具权限限制不等于操作系统沙箱；能力边界和安全保证必须明确说明。
- 不把未来的规划工具、角色体系或交付流程加入通用执行层。

以上是设计约束，不代表相关能力已经实现。
